# Implementation Plan: Backend-Served Content

## Overview

Serve Talks, Location, and Events at request time from a read-only Render Lambda added as a second CloudFront origin, reusing the existing pure talks/site-content modules for byte-parity with the static build. Switch the three content write paths from starting the publisher to issuing a scoped CloudFront invalidation, and relax the static build/verification so it no longer needs materialized dynamic content. No commit, deploy, or AWS mutation.

## Tasks

- [x] 1. Shared render modules inside the asset boundary (`src/`)
  - [x] 1.1 Add a pure S3-backed talk source adapter (`src/lib/talks/s3-source.ts`, with unit tests)
  - [x] 1.2 Render the dynamic regions with Astro's own on-request rendering instead of hand-copied HTML. The `.astro` components render both the static build and the request-time output, so there is one source of truth for the markup and byte-parity is structural rather than asserted against a copied template. Request-time freshness comes from two request-scoped seams: `src/config/site-content-source.ts` (an `AsyncLocalStorage` override for the site content, defaulting to the build-time content) read through `src/config/site-content.ts` + `src/config/site.ts` getters, and a published-talks-snapshot override in `src/lib/talks/gateway-astro.ts`. `src/lib/render-content.ts` reads the content bucket at request time and populates both.
  - [x] 1.3 Markdown parity: the renderer reuses `serializeTalksMarkdown` and `markdownForPath`; `s3-source.test.ts` covers the adapter.

- [x] 2. Dynamic routes served by Astro SSR — `/`, `/index.md`, `/talks/`, and `/talks/index.md` opt out of prerendering (`export const prerender = PRERENDER_DYNAMIC_ROUTE`, patched to a literal `false` for the SSR build by `infra/scripts/build-render-lambda.mjs`). Astro middleware (`src/middleware.ts`) reads the content the requested route needs from S3 and runs the render inside the request-scoped overrides; it shares module identity with the page readers because both are bundled into the SSR server. Home routes read `site/content.v1.json` (location + events); talks routes read `talks/records/`+`talks/decks/`. Draft exclusion, the approved empty archive, the event-type AND topic filters, the JSON-LD (with topic keywords), and the Markdown negotiation all come from the same components/serializers the static build uses. Read failures return a 5xx the edge will not cache as success.

- [x] 3. Render Lambda + CDK origin, behaviors, and caching
  - [x] 3.1 The render Lambda (`infra/functions/render.ts`) wraps the Astro SSR server built by the official `@astrojs/node@11.1.0` adapter (middleware mode), bridging the API Gateway v2 event to the adapter's Node `http` handler and back. `infra/scripts/build-render-lambda.mjs` assembles the package: it patches the four routes' prerender flag to `false`, runs `SALIH_DEV_SSR=1 npm run build`, copies `dist/server` + `dist/client` as siblings (so the adapter's runtime client-directory resolution works), and esbuilds both the handler and the server entry as ESM (createRequire banner, AWS SDK bundled — ESM ignores NODE_PATH). Node 24 arm64, Function URL with `AWS_IAM` auth + CloudFront OAC (non-public).
  - [x] 3.2 The render role is read-only least-privilege: `s3:GetObject` on the content object + talk prefixes and prefix-scoped `s3:ListBucket` on each; no write/StartBuild/CreateInvalidation. A render-specific CloudFront viewer-request function keeps the clean route paths the SSR server matches and negotiates the `.md` alternates (it does NOT append `/index.html`). Behaviors for `/`, `/index.md`, `/talks/`, `/talks/index.md` route to the render origin; the default behavior stays on S3. Caching and resilience (req 5.1/5.3/5.4/5.5): the middleware sets `Cache-Control: public, max-age=0, s-maxage=300, stale-while-revalidate=60, stale-if-error=86400` on a successful dynamic response (browsers always revalidate, the edge caches for 5 min, and CloudFront serves the last good response for up to 24h if the origin or S3 is briefly unavailable), and returns a `no-store` 5xx when the content read fails so the edge never caches the error. The render cache policy keys on `Accept` and sets minTtl 0 / defaultTtl 5m / maxTtl 24h — the 24h max is required for CloudFront to honour the full `stale-if-error` window (it caps stale serving at the lesser of stale-if-error and maxTtl).
  - [x] 3.3 The render decks skip the pdfjs parse at request time (`skipPdfParse` on `validatePdfAsset`): the deck was validated at publish time, and re-parsing would pull the native canvas dependency into the Lambda and re-parse every deck per request for a page count that appears in no public representation. Path safety, existence, non-empty, and PDF-signature checks still run.

- [x] 4. Content writes invalidate instead of publish
  - [x] 4.1 The three handlers (`content-write.ts` → `/`, `/index.md`; `talk-upload-complete.ts` and `talk-records.ts` → `/talks/`, `/talks/index.md`) issue a scoped `cloudfront:CreateInvalidation` instead of `codebuild:StartBuild`, keeping all auth/precondition/conflict/storage behavior and reporting the stored version + invalidation id. IAM in `content-api.ts` grants `cloudfront:CreateInvalidation` scoped to the distribution and passes `DISTRIBUTION_ID`.
  - [x] 4.2 Write-handler tests assert no StartBuild, an invalidation with the right paths, and the response contract without a build id.

- [x] 5. Build no longer requires materialized dynamic content — `verify-static-build.mjs` already treats the empty Talks archive as valid, so the static-route build passes with no materialized API talks. The static publisher build is unchanged (it prerenders every route, including the four dynamic ones, into `dist/`), so a missing content object or empty caches never fail it. The SSR build is a separate invocation used only by the render Lambda's bundling.
